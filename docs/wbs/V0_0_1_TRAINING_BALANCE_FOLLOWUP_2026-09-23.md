# Wanderloom v0.0.1 訓練・初期報酬バランス調整フォローアップ

作成日: 2026-09-23
対象リポジトリ: `arnatoatadaink/wanderloom`
対象バージョン: `v0.0.1`

## 1. 今回のv0.0.1で確定した訓練仕様

初回の訓練は、ブラウザ内だけで完結する10秒のローカルチュートリアルとする。

- WorkerおよびD1とは同期しない。
- 10秒間隔の通信を行わない。
- 探索・claim・inventory更新を発生させない。
- 報酬は付与しない。
- 完了またはスキップ後に、通常のAPI接続を開始する。
- 完了済み状態はブラウザのlocalStorageに保存し、同一ブラウザプロファイルでは再表示しない。

この構成は、初回導入の待ち時間と通信負荷を抑え、サーバー側のチート検知にローカル訓練の経過時間を誤って入力しないためのv0.0.1 baselineである。ローカル完了状態はサーバー上の進行状態や報酬の根拠にはならない。

## 2. 将来の検討案: API訓練ゾーンと初期報酬

初回導入の達成感を補う案として、将来のバランス調整でAPI訓練ゾーンを追加し、初回ユーザーの初期値として一定量の報酬を付与することを検討する。

この報酬は通常の探索報酬ではなく、チュートリアル完了時のオンボーディング助成として扱う。具体的なGold、EXP、アイテム数量は未確定とし、プレイ時間、序盤の購買・装備導線、インフレ率を確認したうえで別途調整する。

API訓練を実装する場合の必須条件は次のとおり。

1. 初回付与をサーバー側で冪等に管理する。
2. リロード、再送、複数タブ、同時実行で二重付与しない。
3. 通常の探索報酬と監査上区別できるイベント種別を持たせる。
4. ローカル訓練の経過時間をチート検知の証拠として扱わない。
5. Worker/D1通信の増加量と、初回導線の完了率を計測する。

## 3. 今回の判断

API訓練ゾーンおよび初期報酬は、`v0.0.1`の統合対象には含めず、次回のゲームバランス調整（M2以降）の候補として保留する。現行版は「初回ローカル固定・Worker非同期・報酬0」で検収済みとする。

ブラウザ上の最小構成の挙動は、ユーザーによる実機確認で完了している。今回のレポートは、将来の初期報酬案を仕様変更として記録するものであり、現行実装がAPI訓練報酬を付与していることを示すものではない。
